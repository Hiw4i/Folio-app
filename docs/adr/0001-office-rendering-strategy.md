# ADR 0001: стратегия рендеринга Office (DOCX/PPTX)

Статус: принято (промежуточно, до сравнительной кампании). Дата: 2026-11-02.
Контекст: план `docs/superpowers/plans/2026-11-01-reader-quality-handoff.md`
(Задачи 9–10), стандарт `docs/READER_QUALITY_STANDARD.md`, скрининг:
`docs/benchmarks/office-engine-comparison.md`.

## Решение

**Сохранить текущий локальный Office-движок** (OOXML → локальные HTML/JS
ресурсы в Android WebView с текстурной композицией в Flutter) как боевой
путь для DOCX и PPTX. Замена не выбирается, пока кандидат не пройдёт
полный протокол сравнения на корпусе.

## Факты, на которых стоит решение

1. Работающая версия подтверждена на двух физических устройствах
   (S25 Ultra — 14/14 GPU; vivo Y33s — 14/14 GPU): текстурная композиция,
   блюр по реальному содержимому, независимая адаптация цвета, лупа,
   selection/copy — регрессий нет (`integration_test/all_glass_test.dart`).
2. Скрининг 2026-11-02: `neo_office` 0.2.0 — Android по-прежнему Planned
   (отсеян); `docx_file_viewer` 1.0.5 — единственный допущенный кандидат
   (DOCX-only), его заявления (поиск, выделение, таблицы, колонтитулы) не
   проверены на нашем корпусе; статус сравнения — «не оценено».
3. Для PPTX пригодных бесплатных офлайн-кандидатов нет. Собственный
   универсальный OOXML layout engine на Flutter — вне плана: его нельзя
   «начать незаметно», а superiority не доказана.
4. Ограничения текущего движка задокументированы
   (`OFFICE_ENGINE_UPDATE.md`, `OFFICE_COMPATIBILITY.md`) и не маскируются
   тестами открытия.

## Последствия

- Блокирующие дефекты совместимости текущего движка исправляются по схеме
  Задачи 10: fixture → воспроизводимый failing test → исправление → полный
  affected corpus. Полная поддержка OOXML не объявляется.
- Замена допускается только по результатам сравнительной кампании
  (proof-of-concept `docx_file_viewer` на корпусе + пороги
  `docs/benchmarks/protocol.md`). Победа определяется отдельно для DOCX и
  PPTX; ухудшение обязательной функции не маскируется суммарным баллом.
- Conversion-стратегия (Office → страницы/PDF) остаётся запасным кандидатом
  с ограниченным кэшем и обязательной проверкой поиска/текстового слоя;
  до доказательной необходимости не реализуется.
- Триггеры пересмотра ADR: (а) завершён proof-of-concept
  `docx_file_viewer` с числами по протоколу; (б) `neo_office` выпускает
  реализованный Android; (в) обнаружен блокирующий дефект текущего
  движка, не исправимый разумной правкой.
- Миграция (если случится) идёт через существующие границы
  renderer/binding; старый путь сохраняется в Git, двойной движок в
  production не держится, bridge/assets удаляются только после полного
  прохождения набора проверок.
